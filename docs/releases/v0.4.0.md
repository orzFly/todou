## What's new

- **An issue can move to another project** — `todou issue transfer 1 --to
  other-project`, or from the card's sidebar. Its old address becomes a
  permanent redirect, so `#N`, comment permalinks and attachment URLs keep
  working; moving it back reclaims the original number.
- **A reference is resolved once, when you write it** — `see #12` is stored
  as `see [#12](/projects/7/issues/12)`, on the target's permanent address.
  One rule replaces the pile every reader used to re-apply: a token is read
  under the project you are writing in, at the moment you submit it.
- **Search takes qualifiers** — `is:`, `state:`, `status:`, `label:`,
  `assignee:`, `harness:`, `session:` alongside free words, parsed by one
  module so the CLI and the web cannot drift. An unknown key stays plain
  text; a value that names nothing is reported rather than refused.
- **The search box does the finding** — it reads what you typed as an issue
  reference and offers that card, completes a project name in any case
  (`ac` → `ACC-`), and remembers what was searched here before.
- **`reporter`, a role between reader and writer** — it opens issues,
  comments, attaches files, and maintains what it posted. Every gate reads
  one catalog now, and the settings page's role table is generated from it.

## Web

- **Comparing spec versions was rebuilt around tables and images** — a paired
  table aligns by row and by column, a swapped screenshot is drawn as a
  change, and a removed cell's image shows in its stand-in.
- **Unchanged blocks fold**, the toolbar counts the changes its arrows step
  through (`n` and `p` from the keyboard), and frontmatter renders as a
  metadata grid compared field by field.
- **Agents and avatars** — an agent's memberships are editable from settings,
  Add agent is a search dropdown with avatars, and an avatar takes a drop or
  a paste, downscaled in the browser to fit the limit.
- **Smaller things** — Move to project and Trash in one MORE ACTIONS menu,
  the whole blank area of a markdown editor is the editor, switching pages
  leaves the header in place, and question options can be selected and copied.

## CLI

- **`issue transfer`** shows the mapping and what the destination cannot take
  before it asks; `--dry-run` prints that and stops.
- **A watch that stays** — `todou watch --follow` and `issue watch --follow`
  deliver every batch instead of exiting with the first. `--follow=stdout`
  writes them out; `--follow=uds` pushes them into the Claude Code session
  that started it, handing back on stdout whatever it cannot account for.
- **`agent can-i-follow`** reports which transport this environment supports;
  `agent opt-out-uds` / `opt-in-uds` set whether it may be offered at all.
- **Attachment names are unique within a card**, so `attach download <name>`
  cannot be ambiguous, and it folds case.
- **Nix installs it** — `nix profile install github:orzFly/todou`, or
  `nix run github:orzFly/todou -- --help` without installing.

## New endpoints

`POST /projects/{slug}/issues/{number}/move`;
`GET /projects/{slug}/search/facets`; `GET /me/agent-memberships`. Nothing was
removed, and every `/api/projects/{…}` route also takes a project id where it
takes a slug — which is what stored links are anchored on.

## Behaviour changes

- **Old text is read under today's grammar.** The gate tying the cross-project
  syntax to when a piece of text was written is gone; the presence of
  cross-project configuration was always the real switch. Measured here: 111
  of 3892 stored segments resolve differently, gaining 460 tokens and losing 12.
- **Attachment filenames are made unique** by migration 0013, which renames
  existing clashes and every stored `image.<ext>`. No link breaks: the URL
  addresses the file by id and the last segment is decoration.
- **Opening an issue is gated the way editing one is.** `POST issues` applied
  `status_id`, `label_ids` and `assignee_ids` unchecked, so a caller without
  `issue.triage` could file straight into Done, labelled and assigned. It is
  refused now. The label catalog moved the other way, admin to writer.
- **A new project may not take an all-digit slug**, since an all-digit path
  segment is read as a project id. Existing ones keep routing, but the
  migration below refuses to start while one exists.

## Breaking changes

**`cross_referenced` is no longer written.** A mention is one `referenced`
event carrying `by_project_id`; local or cross-project is worked out when the
row is displayed, because a stored answer goes stale the moment either card
moves. The old event type and the `by_project` spelling are still read, so an
existing deployment renders correctly from the upgrade onward.

What it costs an older client: a 0.3.1 CLI reading a card on a 0.4.0 server
prints a cross-project mention as though it named the project being read —
`BR-2` where the mention came from `alpha#2`, a number that need not exist
there. The rest of that pairing measured unaffected, a moved card included:
its `moved_in` event prints as an unknown event's raw fields, exit 0.

## Upgrading

1. **Four migrations run on first start** — three per project (move columns,
   agent-context indexes, unique attachment filenames) and one system-wide
   (the address book a moved card redirects through). 0013 is the one that
   changes existing data rather than only its shape.
2. **Then run `todou-server refs migrate` by hand, once.** It converts stored
   tokens into links, reading each under the rules in force where and when it
   was written — the last time those rules are consulted anywhere. Idempotent,
   so `--dry-run` first costs nothing. It refuses to start while any project's
   slug is all digits.
3. **Then `todou-server attachments relabel`** — optional, idempotent,
   cosmetic: it updates link text spelling out a filename 0013 renamed, and
   leaves captions someone wrote themselves alone.
4. **Server and CLI together.** A 0.4.0 CLI against a 0.3.1 server reads
   everything correctly and only `issue transfer` fails, with a 404; the other
   direction mislabels cross-project mentions as above. Both directions were
   measured against the real pair, not inferred.
5. **`refs migrate` has been exercised on PGlite only.** This project's own
   deployment converted 10228 links across 537 cards that way, inside a
   63-second window. The pass carries no PostgreSQL regression test, so a
   `postgres://` deployment should take a backup and read the `--dry-run`
   report before committing to it.
