## What's new

- **Blocking reads as one line.** Blocking several cards shows one verb over
  all of them, and a two-way block shows one group per direction. A reference
  written right after blocking the same card folds under the block, and a
  toggle puts folded events back where they happened.
- **`follow_header` and `follow_footer`** on a server's entry in
  `config.toml` wrap every `--follow=uds` and `--follow=codex` push in your
  own words. Both are unset by default.

## Fixed

- **Spec and issue pages are faster.** At 4× CPU throttle, a keystroke in a
  review comment on a 12k-character spec went from 128 ms to 13 ms and the
  slowest scroll frame from 144 ms to 35 ms. An issue page draws the comments
  nearest the bottom first instead of all 33 in one 1.3 s task, and
  highlights code blocks off the main thread.
- **`todou watch` shows what a card was opened with:**
  `opened "…" (Next · area:cli, kind:bug · @alice)`. Cards opened before the
  upgrade still show the bare line.
- **An inbox row kept for a cleared blocker shows its marker** with
  "Weak unread hints" off.

## Behaviour changes

- **Codex queue batches carry only the activity.** The fixed preamble
  telling the agent how to handle the batch is gone, and so is the matching
  advice in `todou agent can-i-follow`. Set `follow_header` to put
  instructions back in your own words.

## Breaking changes

None.

## Upgrading

- **Either side first.** No migrations, no configuration change, nothing to
  run by hand.
- **A 0.6.6 CLI against this server** works; its `opened` lines just lack
  the new detail.
- **A 0.6.7 CLI against a 0.6.6 server** works, with `opened` lines bare as
  before. `follow_header`/`follow_footer` are CLI-only. Both mixed pairs are read off the code, not run.
