## What's new

- **Global Inbox** — one page for everything waiting on you across every project
  you can see: unread activity from other people, specs awaiting your review,
  unanswered questions. Grouped by project, with a navbar badge and
  mark-all-read at either scope.
- **The issue list groups by status** — Open view, newest state first, each group
  paged independently. `?group=none` restores the flat list.
- **`todou watch` spans projects and idles on pushed events** — `-p a,b` or
  `--all-projects`; a comment wakes a blocked watch in about 0.3s instead of at
  the next poll.
- **Everything reports its own version** — `todou --version`,
  `todou-server --version`, public `GET /api/version`, and a footer showing the
  web and server versions (amber while they differ mid-deploy). One rule
  everywhere: `git describe --tags --always --dirty`.
- **Fewer requests per page** — cold load on a 100-issue project: board 13 → 3,
  issue detail 21 → 8, in-app navigation 12 → 1.

## Agents

- **Harness detection for claude-code, codex, pi and hermes-agent** — every write
  records which harness, session and model produced it, and the agent badge
  copies that harness's own resume command.
- **Nested harnesses are resolved by the parent process tree** on Linux and
  macOS: the innermost harness wins instead of a fixed order. Elsewhere that
  order still decides, and the walk only runs when two harnesses match.
- **A shared `harness` auth profile** — one login covers every harness that has
  no profile of its own. Resolution order: explicit `--profile`/`TODOU_TOKEN`, a
  profile named after the detected harness, `harness`, then the default token.
  Outside a harness it is never consulted.

## Also

- **A review call to action** under the newest unreviewed spec version.
- **`referenced` timeline events** — one row per source, titles wrap, deep links
  land on the row without expanding anything.
- **The project switcher is made of real links** — middle-click, ⌘/Ctrl-click and
  right-click → open in new tab all work again.
- **New issue** moved to the end of the project nav.

## New endpoints

All additive: `GET /activity` (cross-project feed), `GET /events` (one stream per
user; the per-project route stays as a filtered view of the same core),
`GET /me/inbox`, `GET`/`PATCH /me/prefs`, `PUT /me/read` (bulk mark-read),
`GET /api/version` (public, no session needed), and `POST /api/batch`, which
folds same-tick reads into one round trip.

## Behaviour changes

- **`updated_at` now means "this issue saw activity".** Comments, attachments,
  answered questions, spec pushes and spec reviews bump it; being referenced,
  editing a comment and resolving annotations do not. Anything sorted by
  `updated_at` — the web list and board default to it — orders differently than
  on 0.1.0. REST and CLI still default to `sort=created`.
- **`todou watch` filters out your own agent session, not your whole account.**
  Agents sharing one machine account can now see each other. Entries carrying no
  session still fall back to the account, and `--any-actor` turns the filter off.
  **Caveat:** started where no harness variables exist — cron, a detached script
  — it falls back to account scope; declare the session there if you need the
  finer grain. `todou issue watch` did no self-filtering at all before and now
  follows the same rule.

## Breaking changes

None. `todou watch`'s published contract — exit codes, `--json` payload, cursor
interchange, `--debounce` — is byte-for-byte identical, and no endpoint or flag
was removed.

## Upgrading

1. **Server before CLI.** A new CLI against an old server degrades on purpose:
   watch falls back to polling, self-filtering to account scope, and
   multi-project watch fails loudly rather than watching the wrong thing. An old
   CLI against the new server is unaffected.
2. **One new system-database migration** (user preferences) runs on first start.
3. **Images carry a sortable `YYYYMMDD-HHmmss-<sha>` tag** from the UTC commit
   time, alongside `latest`, `0.2`, `0.2.0` and `sha-…`.
