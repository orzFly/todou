## What's new

- **Issue metadata** — namespaced key/value state an external system writes
  on a card: `todou metadata`, `--metadata` on `issue view` and `issue list`,
  a `metadata:<ns>/<key>=<value>` search condition, compare-and-set on every
  write. The server never parses a value. `docs/metadata.md` is the page for
  whoever is integrating.
- **Settled discussion goes behind a counted placeholder** — `comment hide`,
  `/hide-all` in the composer. Hiding declines the questions and resolves the
  annotations it buries; `unhide` restores the body, never the answer.
- **A project you cannot read offers a link to ask for access**, which whoever
  can see it grants or declines. What the refusal prints is a function of what
  you typed, never of anything the server said about the target.
- **An owner arranges their own machines** — a member puts their own agents
  into a project at any role up to their own, without being an admin. That
  ceiling is judged on every path that writes a membership row.
- **The page stops asking after every change** — one event stream per account
  across its tabs, and change events carrying the reader's own inbox row, so a
  client compares instead of refetching. The inbox reads every project sharing
  a database in one pass: 124 queries at 220ms p50 become 23 at 35ms.

## Web

- **Metadata is three tabs** — Browse reads the whole card, Bulk is a
  `ns/key = value` document with heredocs for multiline values, JSON an object
  per namespace. One diff produces every write, so a deletion cannot be lost
  on the way to one.
- **Leaving with unsaved work asks first** — thirteen surfaces behind one
  guard. A failed `/api/me` or project lookup now keeps the draft on screen
  under a connection banner that retires itself, instead of replacing the page.
- **A write stays on the card it was aimed at.** An edit whose attachment
  upload finished after you walked to another card used to send its PATCH
  there — across projects on dedicated placement, over a comment with that id.
- **An edited code fence shows which of its lines moved** in the spec compare
  view, instead of one wash over the whole block.
- **Smaller things** — long labels and unbroken tokens no longer widen the
  page they sit on, anchors land clear of the floating header and the
  composer, completion finds a project from three characters of its name, and
  the composer shows its buttons once you enter it.

## CLI

- **A watch hands over the whole comment**, in a block headed by
  `#comment-<id>`, and an `opened` or reference entry names the card it is
  about. See Breaking changes for what that costs a script.
- **omp is its own harness**, recognised by `OMPCODE` rather than read as
  Claude Code, so its writes stop landing under another agent's session.
  `todou integration install omp` is what makes `--follow=uds` work there.
- **`spec review --comment`** records a summary and annotations without moving
  the verdict — the one review form the account that pushed a version may
  submit — and `--annotations` writes inline comments from the CLI at all.
- **One answer for a prefix** — `A-158` resolves the same in prose and as an
  argument, and `-p` is judged against where the card is now, naming the real
  address when the two disagree.
- **A server entry names the addresses it also answers at.** `instead_of`
  bridges a CLI pointed at an internal address and links copied from the public
  hostname; where the server publishes `http.public_origin`, neither needs any
  client configuration.

## New endpoints and settings

`GET`/`PATCH /projects/{slug}/issues/{number}/metadata`,
`GET …/metadata/namespaces`, `POST …/issues/{number}/comments/hide`,
`POST /projects/{slug}/members`, `GET /projects/{slug}/access-denials` with
`PUT` and `DELETE` per user, `GET /me/refs/resolve`, `GET /me/access-hint`.
Nothing was removed. `auth.oidc.internal_origin`, with per-endpoint overrides,
points the three calls the server makes itself at a cluster-internal address
while the browser keeps following the published one.

## Behaviour changes

- **A hidden comment's body comes back empty** on every merged read; the row
  stays where it was, so `total_count`, the cursors and the page boundaries do
  not move. `include_hidden` turns the blanking off, and a comment asked for by
  id always answers in full.
- **Hiding settles questions and annotations whoever wrote them**, and none of
  it is reversible. "0 unresolved annotations" is a weaker statement than it
  was; the resolution event records that a hide caused it.
- **Attachments are served under a rebuilt content type** — nothing from the
  stored string reaches a header. A script or stylesheet type maps to
  `text/plain`, `charset` survives only on `text/*`, `nosniff` lands on
  download as well as view, and every blob response carries
  `cross-origin-resource-policy: same-origin`.
- **Nobody edits their own membership row** — an admin can no longer demote
  themselves through a one-way door or drop their own row. The owner ceiling
  applies when something writes; the upgrade rewrites no existing membership.
- **Ctrl-Enter submits in every markdown box that has one action**, where it
  inserted a blank line in four of the seven. The blank line is Alt-Enter.

## Breaking changes

**A watch prints a block per entry, not a line.** `todou watch` and
`issue watch` hand back a comment's body whole — a header at column 0,
continuation lines indented two spaces — where they cut it at 120 characters
on one line. A reader taking one line per entry now takes a body's first line;
splitting on `^\S` gives one entry per piece. Truncation moved to `--summary`,
which takes only the `=` form: `--summary 10` now fails with an
extraneous-argument error.

## Upgrading

1. **Three migrations run on first start** — two per project (the metadata
   table, two hide columns on `comments`) and one system-wide (the access
   denial record). All three only add, none rewrites existing data, and there
   is no pass to run by hand.
2. **Server and CLI together.** A 0.5.0 CLI against a 0.4.x server 404s on
   `metadata`, `comment hide`/`unhide` and `project members add`, and its extra
   prefix rung falls back to the directory answer, as that lookup is built to.
   The other direction is quieter and worse: a 0.4.x CLI knows nothing of
   `hidden_at`, so a hidden comment reaches it as a comment with an empty body
   and nothing to say why. That pairing was read off the code rather than
   run — the server half carries tests, the old client's side of it does not.
