## What's new

- **You can @ someone.** `@alice` in a body or a comment notifies them, and it
  reaches their Mentions inbox tab even when the card is otherwise quiet. A
  rename never breaks it.
- **A card can say it waits for another one**, in any project. Nothing gets
  locked: the card still takes comments and status changes. When the blocker
  is closed the wait clears, and whoever declared it hears about it.
- **You can mute a card, or a whole project.** A muted card stays out of your
  inbox and your badge count. Unmuting brings back whatever you missed.
- **Projects have insights: a burn chart and an activity calendar.** Pick a
  day to see the cards active on it. The burn chart counts cards rather than
  estimates, and says `mixed` where it cannot tell what a day held.
- **Every person has a page** listing their cards and projects, with the same
  activity calendar. You only see what you could already read.

## Web

- **Copy link, Copy Markdown, Quote reply and Reference in a new issue** on
  every comment and body.
- **A reference shows up as a chip**, shortened and de-duplicated, with a
  preview of the card on hover.
- **`<details>` folds a block**, and a spec review opens a fold with a change
  or an annotation inside it.

## CLI

- **One CLI reaches two servers.** Give a server a short name and write that
  name wherever a server goes; `config.*.toml` fragments merge into
  `config.toml`, which stays the only file the CLI writes.
- **`todou spec withdraw`** pulls a pending version back for reworking.
- **pi works like the other harnesses**, with its own watch tool and session
  identity.

## Behaviour changes

- **The inbox shows mentions it used to filter out**, so a deployment leaning
  on that filter sees more unread after the upgrade.
- **Moving a card drops the source project's mute rows**, the way a read
  position behaves.
- **An upload answers 415 for a refused type and 413 for an oversized file**,
  where 422 covered both, and a new login cannot be all digits.

## Breaking changes

**`todou-server refs migrate` is gone**, along with reading a REF prefix as of
a past instant. A deployment that never ran that pass has to run it on 0.5.1
first. Nothing else was removed.

## Upgrading

1. **If `refs migrate` never ran here, stop at 0.5.1 and run it there**
   (`docs/deploy.md` carries the pass). From this version on a bare token is
   read under whoever holds that prefix now, so a reference can point at a
   different project, and nothing repairs it afterwards.
2. **The migrations run on first start and only add** — mutes, mentions,
   insights settings, block edges, prefix mirrors, project icons and two
   activity indexes. Nothing to run by hand.
3. **Server and CLI together.** A 0.6.0 CLI against a 0.5.x server 404s on
   `issue block`, `unblock` and `spec withdraw`; a 0.5.1 CLI prints a block
   event as the raw `block_added`. Both directions were read off the code,
   not run.
